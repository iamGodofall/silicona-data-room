# Security Policy

SILICONA contains proprietary semiconductor engineering technology and public evidence materials.

Do not report security issues, secrets, customer information, private PDK material, license credentials, or signing keys in public issues.

Security reports should include the affected component, reproducible steps, security impact, and relevant non-sensitive evidence.

Critical report classes include:

- customer data exposure
- cross-tenant access
- arbitrary code execution
- signing-key compromise
- evidence falsification
- worker isolation bypass
- commercial EDA license-boundary escape

Public benchmark disagreements are not security issues. Use normal technical review channels for evidence questions.
